# vesc_servo

Самодостаточная надстройка над CAN-библиотекой
[**motor_vesc**](https://github.com/kakanada/can_vesc_stm32) для STM32,
превращающая контроллер [VESC](https://vesc-project.com/) с редуктором и
концевиком в полноценный позиционный привод (серву) с адекватным поведением
у цели - без залипаний, забросов по скорости и раскачки, характерных для
штатного position-PID самой вески.

## Зачем это нужно

Штатный контур позиции (Position PID) у VESC на практике у многих проектов
ведёт себя нестабильно: залипает в мёртвой зоне около цели, раскачивается
интегратором, может кратковременно превышать заданную скорость. При этом
контур скорости у VESC работает заметно надёжнее.

`vesc_servo` решает эту проблему переносом контура позиции на сторону
STM32:

- STM32 читает телеметрию вески (угол вала мотора, кастомный статус
  концевика) по CAN;
- STM32 сама считает трапецеидальный профиль скорости и ПИД-коррекцию;
- веске отправляется только **задание скорости** - штатный, хорошо
  работающий контур VESC.

## Самодостаточность - motor_vesc спрятан внутри

`vesc_servo` **сама** создаёт и обслуживает веску внутри себя. `VESC_CAN_Init()`
вызывать не нужно - шина, CAN ID и число полюсов мотора теперь просто поля
`VESC_Servo_Config_t`. Слать команды веске напрямую, разбирать её телеметрию,
подписываться на её колбэк - тоже не нужно, всё это делает сама серва.

**Единственное, что осталось общим с `motor_vesc` и по-прежнему требуется -
подключение прерываний CAN/FDCAN.** Воткните их РОВНО ТАК ЖЕ, как описано в
`motor_vesc.h` - `vesc_servo` их не переопределяет, а лишь использует ту же
периферию изнутри:

```c
/* Бэкенд FDCAN (STM32H7 и т.п.): */
void HAL_FDCAN_RxFifo0Callback(FDCAN_HandleTypeDef *hfdcan, uint32_t RxFifo0ITs) {
    VESC_CAN_RxFifo0_Handler(hfdcan, RxFifo0ITs);
}
void HAL_FDCAN_TxFifoEmptyCallback(FDCAN_HandleTypeDef *hfdcan) {
    VESC_CAN_TxComplete_Handler(hfdcan);
}

/* Бэкенд bxCAN (STM32F4 и т.п.): */
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan) {
    VESC_CAN_RxFifo0_Handler(hcan, 0);
}
void HAL_CAN_TxMailbox0CompleteCallback(CAN_HandleTypeDef *hcan) { VESC_CAN_TxComplete_Handler(hcan); }
void HAL_CAN_TxMailbox1CompleteCallback(CAN_HandleTypeDef *hcan) { VESC_CAN_TxComplete_Handler(hcan); }
void HAL_CAN_TxMailbox2CompleteCallback(CAN_HandleTypeDef *hcan) { VESC_CAN_TxComplete_Handler(hcan); }
```

Всё остальное, что раньше делалось через `motor_vesc` напрямую - не ваша
забота: просто заполните `VESC_Servo_Config_t`, серва сделает всё сама.

## Событийная модель - без ручного тика

`vesc_servo` рассчитана на `motor_vesc` версии 1.1 и старше, где появился
`VESC_CAN_SetTelemetryCallback()` - обработчик, вызываемый автоматически на
каждый принятый статусный пакет вески. `VESC_Servo_Init()` сама подписывается
на него, и весь контур (разворачивание угла, хоуминг, профиль, ПИД)
продвигается сам по мере прихода телеметрии по CAN.

**Вызывать какую-либо функцию-тик в цикле или из таймера не нужно.**

Обратная сторона событийной модели: контур не может сам заметить **полную**
тишину на шине (обработчик просто перестаёт вызываться) - это разобрано в
разделе [Диагностика потери связи](#диагностика-потери-связи) ниже.

## Зона лимитов и рабочий диапазон

Две независимые пары границ, обе - в градусах ВЫХОДНОГО вала:

### Зона лимитов (`limit_min_deg` / `limit_max_deg`)

Жёсткая защита хода. Ни `VESC_Servo_SetPosition()`, ни
`VESC_Servo_SetPositionNormalized()` не могут задать цель за пределами этой
зоны - значение обрезается автоматически. Если фактический угол всё же
оказался снаружи (внешнее воздействие, ошибка в другом месте прошивки и
т.п.) - контур принудительно едет обратно внутрь, **игнорируя гистерезис**
(`error_start_correcting_deg`/`error_stop_deg`): коррекция запускается
немедленно и не останавливается, пока угол не вернётся в зону, даже если
формальная ошибка меньше обычного порога запуска. `home_position_deg` тоже
обязан лежать внутри этой зоны - проверяется при `VESC_Servo_Init()`.

### Рабочий диапазон (`working_min_deg` / `working_max_deg`)

**Это НЕ лимит**, а только шкала для `VESC_Servo_SetPositionNormalized()`:

- `normalized == -1.0` → `working_min_deg`
- `normalized ==  0.0` → середина между `working_min_deg` и `working_max_deg`
- `normalized ==  1.0` → `working_max_deg`

Значения вне `-1.0..1.0` (например `-1.2`) линейно **экстраполируются** за
рабочий диапазон, но итоговый угол всё равно обрезается по **зоне лимитов**,
а не по рабочему диапазону - рабочий диапазон обязан целиком помещаться
внутри зоны лимитов (проверяется при `VESC_Servo_Init()`).

```
limit_min_deg          working_min_deg      working_max_deg          limit_max_deg
     |-----------------------|====================|------------------------|
     ←   -1.2 экстраполирует   -1.0             1.0    1.2 экстраполирует  →
         сюда, но обрежется                                сюда, но обрежется
         по limit_min_deg                                  по limit_max_deg
```

```c
servo_cfg.limit_min_deg   = -100.0f;
servo_cfg.limit_max_deg   =  100.0f;
servo_cfg.working_min_deg =  -90.0f;
servo_cfg.working_max_deg =   90.0f;

VESC_Servo_SetPositionNormalized(g_servo, 0.0f);   /* -> 0°    (середина рабочего диапазона) */
VESC_Servo_SetPositionNormalized(g_servo, 1.0f);   /* -> 90°   (working_max_deg)             */
VESC_Servo_SetPositionNormalized(g_servo, 1.2f);   /* -> 100°  (экстраполяция, но обрезано по limit_max_deg) */
VESC_Servo_SetPositionNormalized(g_servo, 2.0f);   /* -> 100°  (экстраполяция ушла бы на 180°, но обрезано)  */
```

## Свой колбэк телеметрии сервы

Раз слот колбэка телеметрии самой вески занят сервой изнутри, для внешнего
кода, которому тоже нужно реагировать на приход телеметрии (например, чтобы
сразу переслать что-то в общий пакет телеметрии системы), предусмотрен
отдельный, аналогичный по духу колбэк **одним уровнем выше** -
`VESC_Servo_SetTelemetryCallback()`. Он вызывается на каждый принятый
статусный пакет вески (все 7 видов, не только `STATUS_4`), но в обработчик
приходит указатель на серву, а не на веску - внутри сразу доступны и
`s->vesc->telemetry` (сырая телеметрия вески), и `s->telemetry` (готовая
телеметрия сервы: угол выходного вала, цель, состояние - см.
`VESC_Servo_Telemetry_t`), уже свежие на момент вызова.

```c
void OnTelemetry(VESC_Servo_Handle_t *s, VESC_CAN_PacketId_t status_id)
{
    /* удобно скопировать что нужно одним махом, не дожидаясь опроса */
    g_system_telemetry.wheel_angle_deg = s->telemetry.position_deg;
    g_system_telemetry.wheel_current_a = s->vesc->telemetry.current;
}

VESC_Servo_SetTelemetryCallback(g_servo, OnTelemetry);
```

> Как и колбэк `motor_vesc`, этот колбэк вызывается **из прерывания** приёма
> CAN - должен быть быстрым и не блокирующим (никаких `HAL_Delay()`, долгих
> вычислений или ожиданий внутри).

## Возможности

- **Работа через редуктор.** Задаётся передаточное число (`gear_ratio`),
  вся система координат и все команды - в градусах ВЫХОДНОГО вала, а не
  вала мотора.
- **Разворачивание угла мотора (unwrap).** Абсолютный энкодер/Холлы на
  веске меряют угол вала мотора и оборачиваются каждый его оборот -
  библиотека сама накапливает многооборотный угол на каждый приход
  телеметрии позиции (`STATUS_4`).
- **Поиск нуля по концевику вески.** Концевик подключён не к STM32, а к
  самой веске и приходит по CAN в её кастомном статусе. Хоуминг - это
  конечный автомат из двух этапов (подъезд к концевику, отъезд от него до
  отпускания), с автоматическим определением сценария "концевик уже был
  нажат при старте", и с защитными таймаутами на каждый этап.
- **Зона лимитов** - жёсткая аппаратная защита хода (см. раздел выше):
  цель обрезается автоматически, а выход фактического угла за пределы
  зоны принудительно и немедленно корректируется.
- **Рабочий диапазон и нормализованное управление** - `VESC_Servo_SetPositionNormalized()`
  для задания цели значением `-1.0..1.0` вместо градусов (см. раздел выше).
- **Трапецеидальный профиль скорости.** Жёсткие пределы максимальной
  скорости и ускорения выходного вала - устраняет забросы по скорости.
- **ПИД-коррекция слежения за профилем**, а не за конечной целью
  напрямую - и вместе с гистерезисом убирает залипание и дрожание у цели.
- **Гистерезис включения коррекции.** Два независимых порога: коррекция
  запускается только когда ошибка выросла до `error_start_correcting_deg`,
  и останавливается, когда ошибка упала до `error_stop_deg` и ниже. Пока
  коррекция не активна - на веску не шлётся никаких лишних подруливаний.
- **Удержание тормозом у цели** (опционально, включается/выключается
  отдельным переключателем) - защищает ось от смещения вибрацией/внешней
  нагрузкой, пока привод "стоит".
- **Собственная телеметрия сервы** (`VESC_Servo_Telemetry_t`) - готовый
  снимок угла, цели, ошибки слежения и состояния, обновляется сам.
- **Свой колбэк телеметрии сервы** - см. раздел выше.
- **Ручная калибровка позиции "на лету"** - без физического хоуминга,
  если нулевая точка известна из другого источника.
- **API в стиле motor_vesc**: статический пул хэндлов без malloc,
  неблокирующие вызовы, подробные Doxygen-подобные комментарии на каждую
  функцию (в т.ч. внутренние).

## Требования

- Библиотека [`motor_vesc`](https://github.com/kakanada/can_vesc_stm32)
  версии **1.1 или новее** (нужен `VESC_CAN_SetTelemetryCallback`).
- CAN/FDCAN проинициализирован в CubeMX (Start и настройку фильтра
  `vesc_servo` берёт на себя сама, как и `motor_vesc`).
- На веске должен быть настроен кастомный статус №7 с байтом состояния
  концевика (`telemetry.custom_sensor_state`) - см. `motor_vesc.h`.
- В VESC Tool включён и идёт с достаточной частотой статус `STATUS_4`
  (несёт `pid_pos`, служит "тиком" контура позиции - см. предупреждение у
  `max_speed_deg_s` в `vesc_servo.h` про требуемую частоту).
- STM32 HAL (используется `HAL_GetTick()`).

## Установка

Скопируйте `vesc_servo.h` и `vesc_servo.c` в проект рядом с `motor_vesc.h`/
`motor_vesc.c` и добавьте оба `.c` файла в сборку.

## Быстрый старт

```c
#include "vesc_servo.h"

static VESC_Servo_Handle_t *g_servo = NULL;

/* 1. Один раз при старте программы */
void Setup(void)
{
    VESC_Servo_Config_t servo_cfg = {0};

    /* Веска - раньше отдельный VESC_CAN_Init(), теперь прямо тут */
    servo_cfg.hcan       = &hcan1;
    servo_cfg.vesc_id    = 42;
    servo_cfg.pole_count = 14;

    servo_cfg.gear_ratio                  = 20.0f;
    servo_cfg.max_speed_deg_s             = 60.0f;
    servo_cfg.max_accel_deg_s2            = 120.0f;
    servo_cfg.pid_kp                      = 2.0f;
    servo_cfg.pid_ki                      = 0.5f;
    servo_cfg.pid_kd                      = 0.05f;
    servo_cfg.pid_i_max                   = 20.0f;
    servo_cfg.error_start_correcting_deg  = 10.0f;
    servo_cfg.error_stop_deg              = 5.0f;
    servo_cfg.brake_at_target_fraction    = 0.5f;

    /* Зона лимитов - жёсткая защита хода - и рабочий диапазон - шкала для
     * нормализованного управления (см. раздел выше) */
    servo_cfg.limit_min_deg   = -100.0f;
    servo_cfg.limit_max_deg   =  100.0f;
    servo_cfg.working_min_deg =  -90.0f;
    servo_cfg.working_max_deg =   90.0f;

    servo_cfg.limit_switch_pressed_state  = VESC_CUSTOM_SENSOR_PIN_SET;
    servo_cfg.homing_seek_speed_deg_s     = 15.0f;
    servo_cfg.homing_backoff_speed_deg_s  = -10.0f;
    servo_cfg.home_position_deg           = 0.0f;

    /* Сама регистрирует веску и подписывается на её телеметрию -
     * больше ничего вызывать не нужно нигде в проекте. */
    g_servo = VESC_Servo_Init(&servo_cfg);
    VESC_Servo_SetBrakeAtTarget(g_servo, 1U);
}

/* 2. Когда решите, что пора - не обязательно сразу при старте */
void OnHomingRequested(void)
{
    VESC_Servo_StartHoming(g_servo);
}

/* 3. Где угодно в коде, по мере расчёта нового целевого угла */
void OnNewTargetComputed(float target_deg)
{
    if (VESC_Servo_GetState(g_servo) == VESC_SERVO_STATE_READY)
    {
        VESC_Servo_SetPosition(g_servo, target_deg);
        /* либо, если удобнее в диапазоне -1..1 относительно рабочего диапазона: */
        /* c */
    }
}

/* 4. (Опционально) изредка, например раз в секунду - см. раздел
 *    "Диагностика потери связи" ниже */
void HousekeepingTick(void)
{
    VESC_Servo_CheckAlive(g_servo);
}

/* Обязательные HAL-callback'и CAN - единственное, что осталось общим с
 * motor_vesc, см. раздел выше */
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    VESC_CAN_RxFifo0_Handler(hcan, 0);
}
void HAL_CAN_TxMailbox0CompleteCallback(CAN_HandleTypeDef *hcan) { VESC_CAN_TxComplete_Handler(hcan); }
void HAL_CAN_TxMailbox1CompleteCallback(CAN_HandleTypeDef *hcan) { VESC_CAN_TxComplete_Handler(hcan); }
void HAL_CAN_TxMailbox2CompleteCallback(CAN_HandleTypeDef *hcan) { VESC_CAN_TxComplete_Handler(hcan); }
```

Более подробный, аннотированный пример (в т.ч. свой колбэк телеметрии и
нормализованное управление) - см. [`servo_vesc_example.c`](./servo_vesc_example.c).

## Жизненный цикл состояния

```
VESC_Servo_Init()
        |
        v
   DISABLED  --StartHoming()-->  HOMING  --концевик найден-->  READY
        ^                            |                            |
        |                        таймаут                          |
        |                            v                             |
        +<---------------------- FAULT <----- CheckAlive() ---------+
        ^                            |         (потеря телеметрии)
        |                    SetCurrentPosition() / повторный StartHoming()
        +----------------------------+
```

- `DISABLED` - контур выключен, команды не шлются.
- `HOMING` - идёт поиск нуля (`VESC_Servo_GetHomingState()` для этапа).
- `READY` - позиция достоверна, доступен `VESC_Servo_SetPosition()`.
- `FAULT` - хоуминг провалился по таймауту, либо `VESC_Servo_CheckAlive()`
  обнаружила полную потерю связи с веской.

## Диагностика потери связи

Контур продвигается обработчиком телеметрии, который вызывается только
когда пакет **действительно пришёл** - если связь с веской пропадёт
полностью (обрыв шины, зависание вески и т.п.), обработчик просто
перестанет вызываться, и заметить это изнутри самого себя модуль не может.

Подстраховка - две независимые вещи:

1. **Штатный таймаут потери команд самой вески** (настраивается в VESC
   Tool) - если веска перестаёт получать команды дольше этого таймаута,
   она сама останавливает мотор независимо от STM32. Работает всегда, без
   участия `vesc_servo`.
2. **`VESC_Servo_CheckAlive()`** - необязательная функция для тех, кому
   важно, чтобы `VESC_Servo_GetState()` корректно показывал
   `VESC_SERVO_STATE_FAULT` при полной тишине на шине (например для
   индикации на UI). Вызывайте её изредка (раз в секунду и реже вполне
   достаточно) из любого своего периодического места - на сам контур
   позиции она не влияет, только диагностирует и аварийно останавливает
   мотор при обнаружении тишины.

## Полный список API

### Инициализация

| Функция | Описание |
|---|---|
| `VESC_Servo_Init(config)` | Регистрирует веску (шина/CAN ID/число полюсов из конфига) и серву поверх неё, подписывается на телеметрию. Возвращает `NULL` при ошибке конфигурации. |

### Управление движением

| Функция | Описание |
|---|---|
| `VESC_Servo_StartHoming(s)` | Запускает поиск нуля по концевику. Неблокирующая. |
| `VESC_Servo_SetPosition(s, target_deg)` | Задаёт целевой угол выходного вала в градусах, обрезая по зоне лимитов. |
| `VESC_Servo_SetPositionNormalized(s, normalized)` | Задаёт цель в диапазоне `-1.0..1.0` относительно рабочего диапазона (см. раздел выше). |
| `VESC_Servo_SetCurrentPosition(s, actual_position_deg)` | Ручная калибровка позиции без физического хоуминга. |
| `VESC_Servo_Enable(s)` | Включает контур позиции после `Disable()` без повторного хоуминга. |
| `VESC_Servo_Disable(s)` | Немедленно останавливает мотор, выключает контур (хоуминг не сбрасывается). |
| `VESC_Servo_SetBrakeAtTarget(s, enabled)` | Включает/выключает удержание вала тормозом, пока коррекция остановлена. |
| `VESC_Servo_SetTelemetryCallback(s, callback)` | Задаёт свой обработчик на каждый принятый пакет телеметрии вески (см. раздел выше). |
| `VESC_Servo_CheckAlive(s)` | (опционально) диагностика полной потери связи с веской. |

### Чтение состояния

| Функция | Описание |
|---|---|
| `VESC_Servo_GetPositionDeg(s)` | Текущий угол выходного вала, градусы. |
| `VESC_Servo_GetTargetDeg(s)` | Текущая заданная цель, градусы. |
| `VESC_Servo_GetTelemetry(s)` | Указатель на готовый снимок телеметрии сервы (`VESC_Servo_Telemetry_t`). |
| `VESC_Servo_IsHomed(s)` | 1, если хоуминг/калибровка когда-либо успешно завершались. |
| `VESC_Servo_IsAtTarget(s)` | 1, если серва `READY` и коррекция сейчас не активна. |
| `VESC_Servo_GetState(s)` | Общее состояние сервы (`VESC_Servo_State_t`). |
| `VESC_Servo_GetHomingState(s)` | Текущий/последний этап хоуминга (`VESC_Servo_HomingState_t`). |
| `VESC_Servo_ReadLimitSwitch(s)` | Мгновенное состояние концевика по последней телеметрии. |
| `VESC_Servo_GetLimitMinDeg(s)` / `GetLimitMaxDeg(s)` | Границы зоны лимитов из конфига. |
| `VESC_Servo_GetWorkingMinDeg(s)` / `GetWorkingMaxDeg(s)` | Границы рабочего диапазона из конфига. |

Полное описание параметров, единиц измерения и требований к частоте
`STATUS_4` - в комментариях `vesc_servo.h`.

## Важные предостережения

- **Частота `STATUS_4` в VESC Tool критична** - см. подробную формулу
  безопасного периода в комментарии над `max_speed_deg_s` в `vesc_servo.h`.
  Между двумя приходами `STATUS_4` вал мотора не должен успевать
  провернуться больше, чем на пол-оборота.
- **Один слот под колбэк телеметрии на веску.** `VESC_Servo_Init()`
  занимает `VESC_CAN_SetTelemetryCallback()` этой вески под себя. Если
  вашему коду тоже нужно реагировать на приход телеметрии этой же вески -
  используйте `VESC_Servo_SetTelemetryCallback()` (см. раздел выше), а не
  `VESC_CAN_SetTelemetryCallback()` напрямую (это его отключит).
- **Не вызывайте API motor_vesc напрямую** для вески, обёрнутой сервой -
  `VESC_CAN_SendXxx()` будет соревноваться с командами контура позиции.
  Читать `h->telemetry` напрямую (через `s->vesc->telemetry`) - можно, это
  безопасно.
- **Не совмещайте с "памятью положения" нижнего уровня**
  (`VESC_CAN_SetPositionMemoryEnabled` в `motor_vesc`) для той же вески -
  пересчёт офсета там может создать ложный скачок угла, который
  `vesc_servo` примет за реальное вращение вала. Поля памяти положения в
  `VESC_Servo_Config_t` сознательно отсутствуют.
- **Зона лимитов - это программная защита**, работающая через обычный
  контур скорости (см. "Зона лимитов" выше) - она не заменяет физический
  концевик/механический упор там, где цена ошибки высока. Реакция на выход
  за лимиты ограничена той же частотой `STATUS_4`, что и весь остальной
  контур - не жёсткая аппаратная защита с нулевой задержкой.
